## 三、未來後台整合建議（需另行授權後才做）

1. **資料層**：工作資料庫為 SQLite，表結構可直接搬到 Cloudflare D1（同為 SQLite 方言）。`questions.id` 作為跨企劃主鍵；正式題庫試算表保留為原始正本，模組只做「讀取＋分析層」，寫回由匯出檔人工核對後進行。
2. **API 層**：`server.js` 的 JSON 路徑（/api/questions、/api/jobs、/api/ai-results、/api/analyses/:id/review、/api/variants、/api/export…）可平移為 Worker 路由；加上登入（教師帳號）與角色（管理／教師／唯讀）。
3. **公開層**：只開放「教師已核准」的類題（variants.verify_status = teacher_confirmed）與已確認分析的非敏感欄位（年級、課綱代碼、單元、技能、迷思概念、教師追問）；原題、PDF、影片連結、未核准內容不對外。
4. **分類共用**：`vocab/*.json` 應改為讀取共用分類正本（同一份檔或同一 API），版本字串沿用 `rubric_version` 機制，讓素材庫、活動地圖、題庫三處指向同一版本。
5. **三十堂課**：用 `course_links(project='推理數學30堂', lesson='第N堂', position)` 承載既有安排；分析結果不自動改動堂次順序。
6. **AI 交換**：維持「教師複製指令 → 現有訂閱 → 貼回 JSON」；若日後要自動化，仍應以免費額度（例如 Cloudflare Workers AI）為前提並先回報額度估算，不得新增付費 API 金鑰。
7. **身分防火牆**：正式落點若在公開 repo，模組名稱與文件不得出現可反查身分的資訊；原題與匯出檔永遠不進 repo。
